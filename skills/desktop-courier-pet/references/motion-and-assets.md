# 素材与运动实现要点

## 选择最小但充分的绑定方式

| 需求 | 合适的实现 | 验证重点 |
| --- | --- | --- |
| 坐着摇摆 | 脚底支点旋转 + 局部网格变形 | 脚底稳定、耳尾跟随、眨眼无破洞 |
| 走路/攀爬 | 分关节骨骼、支撑/摆动周期、IK 或对应 Live2D 参数 | 足端接触、重心、抓取与换手 |
| 长触手/飘带 | 连续曲线或粒子链 + 弹簧阻尼 + 渐变宽度 | 根部跟随、曲率平滑、端点不抖 |
| 成组角色 | 独立图集/部件、共同主时钟、各自局部绑定 | 数量准确、相位一致、整体边界 |

复用现有渲染器。并非每个任务都需要 Live2D，也不能把仅有位移的贴图称为完整步态。

## 生成可绑定的素材

透明背景应有真实 alpha。画出完整身体和耳尾，留安全边距；组图按等宽单元排开，不互相重叠，不带地面阴影或文字。等宽单元只是搜索范围，实际精确包围盒仍要测量。

明确脸部策略：原生绘制脸时，底图留对应干净区域；完整脸部底图则做纹理变形或局部替换，不叠加新眼睛。PNG 裁边、UV 与本地坐标一起记录，预乘 alpha 要匹配解码和混合方式。

在高密度屏幕检查网格边缘漏缝、透明黑边和半像素接缝。软件网格变形可作为已有原生管线方案，但要测量实际耗时；不要无根据承诺帧率。每屏绘制时先裁除完全不相交的身体，仍保留伸到该屏的递送肢体。

## 三条时间线

```
时间 → 身体/步态 → 当帧姿态与局部根部
输入 → 有限轮转 → 递送状态 + 世界坐标目标
回调 → 校验代次与序号 → 更新字牌 → 独立淡出
当帧根部 + 目标 + 递送状态 → 连续肢体 → 字牌位置
```

身体动作不读取“正在打字”作为暂停条件。输入不重置身体的路线、步态周期或朝向。目标是世界坐标；根部由本地姿态变换得到。渲染和运动必须共用同一变换，包含缩放、翻转与旋转。

走路和伸展共用肢体时，先把支撑姿态作为弹簧/粒子链的目标，再求解。避免每帧求解后把输出大比例拉回静止姿态，下一帧会造成速度与位置不一致。收回接近当前支撑姿态时平滑交还控制。

## 连续输入不丢字牌

每次有效输入给对应肢体增加 strike serial；换角色增加 generation。异步获得字符后先核对两者及当前焦点，再更新。不能以“已经接触过目标”拒绝当次字符，因为字符回调常晚于接触。

单器官保持伸展时直接更新最新字牌和过期时间；多器官有限轮转，忙时替换该器官当前递送，不累积长队。快速输入下视觉递送不必等同于逐字完整播放，但当前分配规则与显示必须稳定。不要处理控制快捷键为普通字符。

字牌沿曲线从末端退回，推荐从约 70 个逻辑像素起调，允许用户改距离；结合屏幕边缘和文字行位置调整。别只把牌子移开却让夹持爪留在错误位置。

## 五只小猫参考参数

本次实现为五个纹理网格，每只独立脚底支点。相同主相位，周期 2.8 秒、摇摆幅度约 0.105 弧度；主摇摆严格同拍，耳尾轻微滞后，眨眼错开。每只约 72×96 逻辑像素，中心间距 74，宽场景约 404。参数是起点，需要根据新素材测量调整。

摇摆关闭平滑收敛到正坐，仍可保留呼吸眨眼和递送；全局暂停冻结时钟。若需求只要坐姿，禁用巡游入口；用户要求屏幕互动后，再接入独立的群体调度，不把五只猫当一个刚体。组宽与离队角色的高度都纳入 home inset、屏幕适配和脏区域计算。


## 五猫群体动作（v0.8）

群体调度与单体运动分层：CatFormation 只决定各成员的脚底位置、朝向、支撑面与动作提示；CatSkeleton 负责每只猫的四肢 IK、立足/摆动周期、脊柱 cubic spline、头耳骨骼与尾巴曲线；FiveCatsMotion 维持共同待机节拍。输入链路只给个体身体小幅反应，不进入群体状态转移。

本次编排为「排排坐 → 顺序走出 → 反向顺序回队 → 最右猫起跳扒边、爬升与挥爪 → 回落 → 排排坐」。出发按猫序延迟 0.22 秒，回程反向延迟；维护原有排序，避免互穿。边框只允许一只领队占用，四只队友错开抬爪与落地反应。不要把它描述成五只同时爬墙。

IK 足端在支撑期保存组坐标位置，身体起伏不移动支撑目标；摆动期走抬脚弧线。腿可做最多 18% 的柔性伸长补偿，避免本体反应让脚脱离接触面。检查数学足端误差、相邻支撑帧滑动与纹理足端偏差，而不只检查骨骼数量。

关闭群体动作时从当前姿态平滑回座，期间禁用手动重新启动；重启或换屏幕直接恢复关闭状态。同步摇摆是另一个开关。脏区域需要包含全部成员的当前包围盒以及上一帧范围，尤其是离开队伍的攀爬猫。

方法参考：[Spine IK 约束](https://us.esotericsoftware.com/spine-ik-constraints)、[Spine 路径约束](https://us.esotericsoftware.com/spine-path-constraints)、[Craig Reynolds 的路径跟随与分离](https://www.red3d.com/cwr/steer/CrowdPath.html)。这里实现的是原生程序化骨骼与曲线，不是 Spine 工程或依赖其运行时。


## 可伸长的猫尾（v0.9）

猫尾使用同一条常驻曲线完成待机和递送，不在伸出时替换图形。八个带阻尼的控制点由有界 cubic Hermite 插值成连续样条；尾根取真实纹理锚点并跟随身体姿态。尾巴在角色身体后方绘制，避免穿过其他猫的脸；字牌的小卷尾仍在前景托住字牌底边，离输入点保留既有距离。

待机动作包括轻扫、问号卷尾、绕尾和甩尾，五只猫有相位和幅度差；行走叠加尾尖滞后。输入后有短预摆、伸出时沿曲线传播的波动、接触轻点和回收余摆。快速复用已经伸出的尾巴不能反复从零预摆，否则连续打字会卡住。

将「形变目标归零」和「实际曲线回到身边」分开。控制点的惯性可能让几何仍跨屏；回收状态要等待实际控制链接近静止形状，才能恢复待机边界裁剪。只看插值参数会提前裁断或突然拉回尾巴。

字符序号、焦点校验和隐私逻辑复用原有输入管线。尾巴小动作使用独立持久化开关 `fiveCatsTailPlay`；关闭仅抑制待机花样，保留伸尾递字。明确暂停冻结可见曲线。用真实曲线验证 C1 接缝、根部附着、速度上限、远处点击、回收、关闭后递字和暂停；还要检查群体路线与无输入基准一致。
