# macOS 输入与窗口

这些是实现和排错要点，具体 API 行为、系统版本变化与新增方案应查 Apple 官方文档，不能据此宣称所有应用兼容。

## 先测位置，再做美术

测试已聚焦 AX 元素、选区/插入范围以及相应 bounds，区分精确插入点、整个文本控件 bounds 和没有有效位置。检查安全输入/密码角色后再取字符。原生文本、浏览器、第三方聊天应用分别验证；一个通过不代表其他通过。

CGEvent 的 Unicode 是键盘事件信息，不能当作输入法最终提交文本。没有 AX 插入点的应用可能需要明确的用户定位降级；不要把最后一次鼠标位置静默描述为精确光标。若用户要求研究输入法级兼容，再评估 InputMethodKit 等方案及其安装、切换和文本提交生命周期；不要给普通角色换肤任务额外装输入法。

## 坐标与覆盖层

- 选一种全局逻辑坐标作为内部标准，集中做 AX/CGEvent 与 AppKit 之间转换。典型 top-left 与 bottom-left 转换参照主显示器坐标系，不能用目标屏幕高度随意翻转。
- `NSScreen.frame` 可有负原点；用 `visibleFrame` 放身体，避免菜单栏与 Dock。Retina backing pixels 只用于栅格分辨率，不能重复缩放全局逻辑位置。
- 每个显示器创建透明、不激活、鼠标穿透的覆盖窗口，分别绘制其可见区域。跨屏肢体用同一世界坐标目标，不从各自屏幕重新插值。
- 重新连接显示器或缩放时更新世界布局、身体位置和绘制范围；不要重新开启用户关闭的动作。

## 监听和生命周期

使用系统允许的事件监听/辅助功能接口。事件线程只做有界工作，动画在独立刷新循环。字符异步回调核对焦点应用、当前安全状态、角色代次、输入序号与过期时间。

既有“显示字母”开关必须保留。日志只记录计数、状态、坐标类别和错误原因，不写入实际输入文本；健康文件也不能出现字母内容。切入安全输入或丢失可信目标时及时清除字牌。

## 构建和权限

保持 bundle identifier 和已选签名方案稳定。若已有合适开发签名则复用；ad hoc 重新构建可能改变系统识别，先验证实际的 trusted/inputConnected 状态。仅在证据表明确实缺权限时，才让用户开启当前构建的系统授权，并给出正确应用路径。

不要改 TCC 数据库，也不要假称可以自动赋予系统隐私授权。本地重启前验证确切应用路径与进程，避免广泛 pkill。先暂存并验证新包，再替换已知工作区构建；不覆盖无关用户安装。

## 最小证据

记录构建版本、实际资源加载、显示屏布局、AX 信任与输入连接状态、原生菜单切换、开关重启恢复。真实输入测试记录测试应用/输入类型及是否取得位置，不记录内容。模拟动画通过与真实系统输入通过要分别报告。
