# 打字递送桌宠

把角色、动作和系统输入接成一个真正可运行的桌宠。优先扩展已有工程，保留用户已经确认的形象、行为和权限设置。用户只要形象、计划或提示词时，只完成所请求的阶段。

## 先确认范围

1. 检查工作区和 `AGENTS.md`，定位应用入口、素材目录、渲染器、输入监听、动画状态与构建脚本。不要仅因为项目目录包含 BongoCat 就假定它是 Live2D 模型。
2. 从当前对话提取：平台、角色数量、风格、递送器官、是否移动、开关、现有兼容性限制。缺失的可逆美术细节用合理默认值；缺少目标平台等会改变架构的信息才询问。
3. 对新项目，**先验证正在打字的位置能否取得**，再扩展完整美术。对已有工程，先复用输入链路，新增角色不等于修复应用兼容性。

## 按任务读取参考

- 要完整可复制的创作指令：读 [prompt-template.md](references/prompt-template.md)，填入参数交付，不必启动整个制作流程。
- 要生成角色、绑定动作或解决肢体问题：读 [motion-and-assets.md](references/motion-and-assets.md)。
- macOS 全局输入、多屏或权限问题：读 [native-macos.md](references/native-macos.md)。其他平台先研究其实际输入与窗口能力，不照搬 macOS 接口。
- 已有 `work/octopus-pet` 工程：再读 [taro-project.md](references/taro-project.md)。该文件是项目接入说明，不是所有桌宠的固定目录规范。

## 制作流程

### 1. 写出角色的运动规则

记录每个角色的器官数、根部位置、待机、移动、伸展、接触、保持和回收行为。单舌头连续输入应就地更新字符；八触手轮流分配；五猫角色使用五个独立身体和一个共同摇摆时钟。坐姿角色无需强行加入巡游。

### 2. 生成与检查素材

使用当前会话可用的图片生成工具，按适用的 imagegen skill 操作。优先真实透明 PNG，保留原始图和完整提示词。角色数量、构图、肢体完整性和可拆分性必须目视检查。素材是否自带眼睛和嘴巴要明确，避免运行时叠出第二张脸。

测量素材的包围盒、基线、旋转支点和附着点，再绑定动画。需要改画时用图片编辑工具；运行时裁取图集和绘制网格属于动画管线。不要用白底截图冒充透明素材。

### 3. 实现三条可并行的更新链路

- **身体动作**：待机、行走、攀爬、摇摆；明确支撑点、步态与次级摆动。
- **递送动作**：世界坐标目标、随身体移动的根部、伸出/保持/回收及有限的轮流分配。
- **字符展示**：当前字符、异步序号、位置偏移和淡出。字符更新不依赖于肢体刚好再次碰到目标。

打字和点击不能冻结身体时钟或重置移动路线。显式“暂停桌宠”才可冻结全部动作。关闭巡游后保留输入响应；群体摇摆需要自己的开关。开关、角色选择和大小等已有设置应保存，切屏、换角色和重启不得悄悄重新开启。

### 4. 接入宿主应用

复用原有菜单、角色目录和偏好设置。覆盖层不抢焦点、不拦鼠标。字符牌沿递送路径退后，留出输入区；所有端点、字牌和宽角色组都纳入绘制范围。密码框不提取、不显示字符，不持久化或上传键入内容。

构建到可回退的新输出，检查签名、版本、资源和运行健康，再替换本项目的已知应用。按用户已授权的范围完成本地运行；不要自动发布、改系统隐私数据库或终止未经确认的其他进程。

### 5. 验证并交付

按变化选择有意义的验证，不创建只重复实现的测试。至少覆盖本次新增行为的正常、连续输入、开关和恢复路径。角色接入检查菜单、资源与设置；动画检查根部不断开、坐标有限、无明显瞬移、支撑点合理；跨屏变化检查负坐标和缩放。

导出使用实际渲染器的动图或视频，查看摇摆极值、眨眼、首次伸出、持续输入、回收、关动画等关键时刻。截图只能证明该帧，明确区分动态模拟、抽帧检查、视频播放和真实输入验证。

适用 Taro 素材格式时运行 `scripts/validate_pet_assets.py`；有自定义格式则用项目自身验证，不强改格式。交付运行入口、如何选择角色/关闭动作、预览、源文件及已知限制。报告真实完成的验证，未验证的微信或输入法兼容性不能写成已解决。
